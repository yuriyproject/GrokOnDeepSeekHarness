# Review of 2026-11-05: findings and status

An independent read-only review by Grok Build, followed by fixes in this repository. The review
was checked against the code before fixing; each fix has a test unless noted.

## Fixed

| # | Problem | What happened before | Fix |
|---|---|---|---|
| 1 | Text or thoughts arriving while a tool still ran | The activity group was closed early and the still-running tool was recorded as failed, so its real output was lost. | Text is held back while any tool in the group is pending and replayed when the lane is quiet. Test: `turn.spec.js`. |
| 2 | Child environment not minimal | DSH builds the child environment as "scrubbed parent environment plus overlay". Only credential-shaped names and `DSH_*` were scrubbed, so other parent variables (for example `NODE_OPTIONS`) were still inherited. `delete` on the overlay removes nothing. | The overlay now adds an explicit `undefined` tombstone for every parent variable not on the allow-list, which DSH treats as "remove". `XAI_API_KEY` is dropped in any letter case, also from `config.env`. Test: `grok-env.spec.js`. |
| 3 | Windows path tricks in the file bridge | Win32 ignores trailing dots and spaces, so `sub\.. \..\x` could pass the prefix check. File writes needed no approval. | Segments that become `.` or `..` after stripping, device names (`CON`, `NUL`, `COMn`, `LPTn`), `:` streams and NUL bytes are rejected. Containment uses `path.relative` (case-insensitive on Windows) and is checked again on the final path. Test: `hardening.spec.js`. |
| 4 | Cancel and unload could hang | `session/prompt` was awaited without the abort signal; a Grok process that ignored `session/cancel` blocked the turn and plugin unload forever. | The prompt is raced with the abort signal (3 s grace) and the turn ends as `aborted`. Agent disposal waits at most `disposeGraceMs`. |
| 5 | Idle timer killed the CLI mid-open | A 30 s idle timer could fire between `closeSession` and the next `session/new` or `resume`. | In-flight opens are counted; the timer is cleared whenever the process is requested and never stops a process while a session opens. |
| 6 | Lost resume silently gave an empty session | If Grok could not resume or load its session, a new one was created and the DSH chat looked intact while the model had no context. | The host reports `contextLost`; the agent prepends a bounded (20,000 characters, newest first) replay of the stored user and assistant text to the next prompt, marked as restored context. |
| 11 | Approval card without the command; unapproved writes | The card showed only the tool title ("Bash"). A client-side file write ran with no prompt if Grok had its own auto-approve. | The card shows the command or path, redacted and shortened. A file write with no permission granted in the same turn asks through DSH. |
| 12 | `/always-approve` | It was sent to Grok as chat text and could flip Grok's own auto-approve while the user believed a local switch changed. DSH policy `never` means "never approve", so it cannot back this command. | The command is withheld, also when Grok advertises it. Use DSH Full access instead. |
| 17 | Wrong process directory | The Grok process started in its own state directory. | It starts in the system temp directory; sessions get their workspace explicitly. |
| 18 | Fragile session map | A corrupt file stopped the plugin from loading; two DSH processes could overwrite each other. | A corrupt file is renamed aside and the map starts empty. Writes merge with the file under an exclusive lock. |
| 19 | Cached failed registration | One failed projection registration broke every later session until restart. | The failure is not cached. |
| 7 | Loopback trust used only the Host header | A LAN peer could send `Host: 127.0.0.1`. | Both socket ends must be loopback. The stderr tail in errors is redacted. |
| 14, 16, 21, 22, 23 | Stale snapshot response, unbounded file reads and writes, Chinese-only fallback text, preset menu active after start, home lookup ignoring its argument | | Fixed. File reads and writes are capped at 8 MiB. |

## Deferred (not bugs of the current feature set)

- 8: model and effort are process-global (one shared Grok process).
- 9: `steer` waits for the whole Grok turn.
- 10: tool arguments are frozen when the first ACP update arrives.
- 13, 15: edge cases of the harness switch and the DSH model seat.
- 20: pasted images are sent as a text placeholder.
- Ideas: sandbox wrapper for the Grok process, forwarding DSH MCP servers, DSH terminal for Grok shell
  tools, child sessions for `/goal` and `/workflow`, another ACP agent through the same router.

## Behaviour changes to know

- While a tool runs, Grok text is shown after the tool settles instead of live.
- A file write that no permission covered now opens an approval.
- `/always-approve` is no longer offered.
