# GrokOnDeepSeekHarness

`dsh-grok-acp` (пакет `0.4.0-dsh0.2.2-rc.1`) — плагин для DeepSeek Harness (DSH) 0.2.2-rc.1 Web. Он ставит Grok Build корневым агентом сессии DSH, а чат остаётся интерфейсом DSH.

## Задача

В DSH Web уже есть журнал сессии, строки инструментов, диффы, запросы разрешений и команды через `/`. Grok Build — отдельный CLI кодинг-агента: вход по OAuth, протокол Agent Client Protocol (ACP). Мост запускает этот CLI из интерфейса DSH, чтобы пользоваться входом Grok без ключа xAI API. Штатный агент DSH никуда не девается и остаётся режимом по умолчанию.

## Что вы получаете

- Переключатель **DSH / Grok Build** рядом с полем ввода. По умолчанию выбран DSH. Переключать можно только пустую сессию. Если CLI Grok не найден, DSH всё равно стартует. Переключатель показывает «Harness unavailable», а причина лежит во всплывающей подсказке.
- Родные строки инструментов DSH. Обычные вызовы собираются в одну группу `grok_build_activity` (дочерние события `tool/ptc-dispatch*`); дифф внутри группы остаётся текстом. Каждая правка файла — отдельный шаг и карточка диффа.
- Разрешения в UI DSH. На карточке показана команда или путь: текст укорочен, секреты вырезаны. Запись файла, которую не покрыло разрешение, тоже спрашивает подтверждение.
- Модель и effort у каждой Grok-сессии свои. Grok Build CLI 1.0.70 отдавал модели `grok-4.7`, `grok-4.7-build-fast`, `grok-4.6` и `grok-4.5` и effort `xhigh`, `high`, `medium`, `low`. Вторая сессия не меняет выбор первой.
- Команды через `/` в Grok-сессии: `/usage` и `/cost`, `/model` и `/models`, `/effort`, `/grok-model`, `/context`, `/compact`, `/session-info` (ещё `/status` и `/info`), `/btw`, `/deep-research`, `/workflow` и `/goal`. Команды `/always-approve` нет.
- Продолжение после перезапуска DSH: журнал сессии и карта `grok-harness-sessions.json` в каталоге `DSH_HOME`. Идентификатор сессии Grok ещё лежит игнорируемой записью в журнале DSH и читается только если в карте его нет.
- Вложения-картинки. В журнал пишется ссылка, не байты. Агент читает хранилище вложений DSH и шлёт ACP-содержимое картинки, если CLI заявил поддержку; иначе уходит именная заглушка.
- Значок-предупреждение, если путь рабочей области лежит в папке облачной синхронизации (OneDrive, Dropbox и похожие). Проверка — `isCloudSyncedPath` в `lib/cloud-path.js`.
- Необязательная пересылка MCP. В `cordis.patch.yml` параметр `forwardMcp` по умолчанию `false`. При `true` в Grok уходят активные строки хоста `dsh-mcp-client`. Серверы внутри пресета и `cwd` для stdio не передаются. В журналах значения секретов маскируются.

`steer` обрывает текущий ход (причина `user`) и начинает следующий с новым текстом. В уже идущий prompt ACP текст не вставляет.

## Как это устроено

Браузер остаётся клиентом DSH Web. Патч бандла отключает штатное место модели, объявляет пресет `grok-build` и подменяет фабрику агента маршрутизатором. На пустой сессии маршрутизатор оставляет официальный цикл DSH или поднимает агента Grok. Агент говорит с одним общим дочерним процессом Grok по ACP (`grok agent --no-leader stdio`) и пишет обычный журнал сессии DSH. Клиент ходит на loopback-маршрут `/grok-acp/session` за переключателем, местом модели Grok и признаком облачной папки.

```text
browser (DSH Web)                 DSH host                         Grok CLI
  switch, model seat, tool rows     router: DSH loop or Grok
  approvals and / commands          grok-agent writes the DSH log
        |                           /grok-acp/session (loopback)
        +-------- same-origin HTTP --------+
                                    acp-connection, stdio JSON-RPC
                                              |
                                              +-- grok agent --no-leader stdio
```

## Безопасность и данные

Ключа xAI API нет. `XAI_API_KEY` выбрасывается в любом регистре букв, в том числе если его положили в `env` строки плагина. Вход — только OAuth CLI Grok Build (`grok login`). Плагин не читает `auth.json`.

Дочерний процесс получает allow-list переменных окружения. Все прочие переменные родителя в overlay ставятся в `undefined`: именно так DSH их снимает. `GROK_HOME` берётся из конфигурации. Процесс стартует с `shell: false`, массивом аргументов, абсолютным путём к исполняемому файлу и рабочим каталогом во временной папке системы. Рабочая область сессии передаётся отдельно.

Доступ к файлам по ACP не выходит за эту рабочую область. Проверяются символические ссылки, хвостовые точки в сегментах Windows, имена устройств и потоки. Чтение и запись обрезаются на 8 МиБ. В патче бандла `yoloMode` и `allowOutsideWorkspace` равны `false`. Сессия DSH в режиме `danger-full-access` по-прежнему видит файлы всего хоста и не спрашивает разрешения. Ответ на запрос одноразовый: `allowed-once`, `rejected`, `cancelled` или `unavailable`. Мост не шлёт `allow_always` и `reject_always`.

HTTP-маршрут требует loopback с обоих концов сокета, проверяет Host и Origin, принимает только JSON и режет тело на 64 КБ. Клиент вызывает маршрут на том же origin.

Аудит только чтением коммита апстрима `e7111741a67269503d1f71c379902354687da7f8` и npm-пакета `dsh-grok-acp@0.3.4` не нашёл install-скриптов, сетевого клиента, обфускации и чтения `auth.json`. В том пакете `XAI_API_KEY` ещё пробрасывался; этот форк проброс убрал. Независимое ревью от 2026-11-05 ([REVIEW-2026-11-05.md](REVIEW-2026-11-05.md)) поправило окружение процесса, пути Windows, запись без разрешения, зависания отмены и выгрузки, таймер простоя, тихое пустое возобновление, проверку loopback и предел файла 8 МиБ. Что осталось: обёртки-песочницы вокруг процесса Grok нет, а Full access — по-прежнему режим всей сессии DSH.

## Требования и быстрый старт

- DeepSeek Harness `0.2.2-rc.1` (приложение 44.7.0 или CLI `dsh` того же релиза).
- Node.js `^22.19` или `>=24`, если собирать из исходников.
- Grok Build CLI, уже вошедший через `grok login`. В проверках этого репозитория был CLI 1.0.70.
- Код рассчитан и на Windows, и на macOS, и на Linux. Журнал проверки снят только на Windows 11.

Полный порядок, жёсткие правила и разбор сбоев — в [INSTALL-FOR-AGENTS.md](INSTALL-FOR-AGENTS.md). Старт в шесть строк:

```text
npm ci --legacy-peer-deps
npm run check
dsh <profile> --from-default-profile web --no-open --port 6300
dsh plugin --profile <profile> add <path-or-tarball>
# задайте GROK_HOME и при необходимости GROK_COMMAND; не задавайте XAI_API_KEY
dsh <profile> --no-open --port 6300
```

Откройте напечатанный URL (в нём одноразовый токен, его не рассылают), создайте сессию и выберите Grok Build. Ставьте плагин только через `dsh plugin add`. Профиль `desktop` не трогайте, пока приложение DSH запущено.

## Статус и ограничения

- DSH 0.2.x — предварительная версия. Слоты клиента и Remote API от релиза к релизу могут меняться.
- Все peer-зависимости `@deepseek-ai/dsh-*` зафиксированы как `0.2.2-rc.1`. Следующий релиз DSH потребует новой сборки этого пакета. Исключение по версии — не тот выход.
- Проверка записана на Windows 11 (DSH 0.2.2-rc.1, Grok Build CLI 1.0.70). macOS и Linux не гоняли.
- Настоящий ход DeepSeek в режиме DSH не выполнялся. В тестовом профиле не было учётных данных DeepSeek. Фабрику DSH, пресеты и каталог моделей проверяли.
- Только юнит-тесты, без живого прогона: `forwardMcp: true` на настоящем MCP-сервере, `steer` посреди хода, вставленная картинка, неудачное переключение и значок облачной папки в браузере.
- Правка файла ждёт, пока закончатся более ранние обычные вызовы, и идёт своим шагом. Текст, пришедший во время инструмента, показывается после того, как инструмент завершился.
- Если Grok не смог возобновить или загрузить сессию, хост ставит `contextLost` и добавляет в начало следующего prompt текст пользователя и ассистента из журнала, сначала новые, не длиннее 20 000 символов.
- Рабочая область DSH по умолчанию — `Documents\deepseek-harness\default-workspace`. Если «Документы» перенаправлены в облачную папку, для Grok выберите область вне её.
- Название тарифа приходит из CLI. В журнале проверки аккаунт Ultra отображался как «SuperGrok Heavy».
- В этой сборке нет обёртки-песочницы для процесса Grok, терминала DSH для shell-инструментов Grok и дочерних сессий для `/goal` и `/workflow`.
